# Client.txt line shapes the tracker relies on

Observed shapes (English client). The parser lives in
`crates/core/src/log/parser.rs`; every pattern is anchored to the standard
prefix `YYYY/MM/DD HH:MM:SS <uptime_ms> <hex> [LEVEL Client <pid>]` followed
by a body:

| Event | Body shape | Notes |
|---|---|---|
| Zone entered | `: You have entered <Zone Name>.` | Requires **local chat enabled** in-game; also marks the end of a loading screen |
| Instance details | `Got Instance Details …` | Start of a loading screen; the gap to the next zone entry is recorded as `load_ms` |
| Area generation | `Generating level <N> area "<id>"( with seed <N>)?` | `<id>` is the internal area id: campaign `1_4_2`-style, maps `MapWorlds…`, hideouts contain `Hideout`. Monster level `<N>` disambiguates duplicate zone names; map tier = level − 67 |
| Level up | `: <Char> (<Class>) is now level <N>` | |
| Death | `: <Char> has been slain.` | |
| AFK toggle | `: AFK mode is now ON/OFF…` | Parsed, currently unused (reserved for pause detection) |

Chat lines can *contain* any of these phrases (`: SomeGuy: You have entered …`)
but never match, because system-message bodies start with `: ` followed
directly by the message — the parser tests pin this down.

The `<uptime_ms>` counter gives millisecond deltas and **resets when the game
restarts** — the tracker uses a backwards jump to invalidate its open-instance
cache (instances do not survive a client restart).

## Fixture provenance

The files in `crates/core/tests/fixtures/` are **synthetic** — shaped after
the formats documented by the community tools this app follows (LiveSplit
PoE autosplitters, poe-log-monitor, mapwatch, TraXile) since the game does not
run in the dev environment:

- `full_run.txt` — generated by `scripts/gen-fixture.mjs` (regenerate with
  `node scripts/gen-fixture.mjs`): a complete acts 1–10 golden-path run with
  exact 60s dwells and 3s loads, level-ups, one death, chat noise, first map.
- `backtrack_death.txt`, `act6_coast.txt`, `maps_t1_t3.txt` — hand-written
  edge-case scenarios (see the tests that consume them).
